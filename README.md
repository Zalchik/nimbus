# Nimbus

Лёгкий клиент для Windows на [Xray-core](https://github.com/XTLS/Xray-core).

Конфиги из подписки Nimbus запускает **как есть**: с балансировщиком, `burstObservatory` и маршрутизацией провайдера. Клиенты, которые пересобирают такие конфиги под sing-box или mihomo, это теряют. Отсюда и скорость.

## Возможности

- **Подписки.** Полные Xray JSON-конфиги и обычные ссылки (base64 или текст). Трафик и срок подписки, автообновление. User-Agent настраивается: от него зависит, в каком формате панель отдаёт подписку.
- **Протоколы.** VLESS (Reality, XTLS Vision, XHTTP, gRPC, WS, HTTPUpgrade), VMess, Trojan, Shadowsocks (включая 2022), Hysteria2 (salamander, port hopping), SOCKS5, WireGuard.
- **Режимы.** Системный прокси или **TUN**: весь трафик идёт через TUN, устроенный как в [Throne](https://github.com/throneproj/Throne). Адаптер держит [sing-box](https://github.com/SagerNet/sing-box) на собственном TCP/IP-стеке sing-tun (auto_route, hijack-dns, sniffing) и передаёт соединения в Xray через локальный SOCKS-мост, так что конфиги подписки по-прежнему работают как есть. Соединения самого Xray привязаны к физическому адаптеру и не возвращаются в туннель. При смене сети Nimbus переподключается сам.
- **Kill switch.** В TUN включает strict route: Windows Filtering Platform блокирует DNS мимо туннеля и IPv6, если туннель его не несёт. В режиме прокси при падении ядра прокси остаётся включённым, и трафик не уходит напрямую.
- **Маршрутизация.** «Всё через VPN» или «российские сайты напрямую», блокировка рекламы, локальные сети напрямую, обновление geoip/geosite.
- **DNS.** Удалённый DoH через туннель, прямой DNS, FakeDNS (в TUN).
- **Дополнительно.** Mux, фрагментация TLS ClientHello, sniffing.
- **Пинг.** Реальная задержка через сам сервер, все серверы параллельно.
- **Приложение.** Трей, автозапуск, автоподключение, живая скорость, логи.

## Использование

1. Нажмите «＋ Добавить» и вставьте URL подписки (или ссылки `vless://…`). Можно скопировать URL и нажать «Из буфера».
2. Выберите сервер: двойной щелчок подключает.
3. Режим «TUN» нужен для программ и игр, которые не используют системный прокси. Для него Nimbus перезапустится от имени администратора.

## Установка, обновление, portable

Nimbus выходит в двух вариантах:

- **Установщик** `Nimbus-<версия>-setup.exe`. Ставит программу в `%LOCALAPPDATA%\Programs\Nimbus` без прав администратора, данные хранит в `%APPDATA%\Nimbus`. Чтобы обновиться, достаточно запустить установщик новой версии: он сам закроет запущенный Nimbus (с отключением и возвратом настроек прокси) и заменит файлы. Настройки и подписки сохраняются. Удалить программу можно через «Параметры → Приложения → Nimbus → Удалить». Деинсталлятор спросит, удалять ли данные.
- **Portable** `Nimbus-<версия>-portable.zip`. Распакуйте куда угодно, кроме `Program Files`. Все данные хранятся в папке `data` рядом с `Nimbus.exe`, так что папку можно переносить или носить на флешке. Обновление: распакуйте новую версию поверх старой, папка `data` останется. Признак portable-режима — файл `portable` рядом с exe; без него данные хранятся в `%APPDATA%\Nimbus`. Если папка недоступна для записи, Nimbus тоже использует `%APPDATA%\Nimbus`.

Тема (тёмная или светлая) переключается тумблером в левом верхнем углу окна.

Если система упадёт во время подключения, Nimbus при следующем запуске сам вернёт прежние настройки прокси.

## Сборка из исходников

```bash
pip install PySide6 httpx pyinstaller Pillow
python tests/test_core_logic.py
python build.py
```

Результат появляется в `dist/<версия>/`: папка `Nimbus`, `Nimbus-<версия>-portable.zip` и `Nimbus-<версия>-setup.exe`. Для установщика нужен [Inno Setup 6](https://jrsoftware.org/isinfo.php) (`winget install JRSoftware.InnoSetup`); скрипт лежит в `installer/nimbus.iss`. Для нового релиза поменяйте `VERSION` в `nimbus/paths.py`. `AppId` в скрипте не меняйте никогда: по нему установщик находит уже установленный Nimbus и обновляет его.

В `vendor/xray/` должны лежать `xray.exe` и `geoip.dat`/`geosite.dat` из [релиза Xray-core](https://github.com/XTLS/Xray-core/releases), а также `sing-box.exe` (windows-amd64, версия 1.15+: в ней sing-tun работает на собственном стеке, как в Throne) из [релиза sing-box](https://github.com/SagerNet/sing-box/releases) и его лицензия под именем `LICENSE-sing-box`. Wintun встроен в sing-box, отдельный `wintun.dll` не нужен.
